# Decision Records — agent guide

Guide to decision records (DRs) for any part of an organization: guide,
tutorial, templates, worked examples, checklists, and help, organized by
locale, plus a SvelteKit website and Claude Code skills.

**Read [spec/](spec/README.md) first. It is the single source of truth.** If
this file, a README, a skill, `llms.txt`, or the site disagrees with the spec,
fix that file to match the spec (or change the spec deliberately).

## Map

| Path | What |

## Rules

- Edit English in `locales/en-us`, then translate; never the reverse.
- In each content directory `README.md` is a symlink to `index.md`
  (`ln -s index.md README.md`); edit `index.md` only.
- `locales/en-us/index.md` is generated: edit `README.md`, then run
  `python3 scripts/build-root-index.py`, then `python3 scripts/build-english-variants.py`
  (regenerates `en-001`, `en-gb`, `en-gb-oxendict`, `cy-001`; never hand-edit those).
- Never hand-edit `.locale-peer-id` files.
- Never hand-edit `decision-records.github.io/src/content/` or
  `src/lib/locale-*.json`; they are generated by `pnpm run content`.
- Translate locales one at a time, not with parallel subagents.
- Keep product names, code, and URLs untranslated.
- When counts change (sections, examples, locales), update the spec,
  `static/llms.txt`/`llms.json` (regenerated by `pnpm run content`), and the
  skills together.

## Before committing

1. `python3 scripts/audit-locales.py` exits 0.
2. In `decision-records.github.io`: `pnpm run content` leaves no uncommitted
   changes, `pnpm test` and `pnpm run check` pass, and after `pnpm run build`,
   `pnpm run verify` and `pnpm run a11y` report 0 problems. CI
   (`.github/workflows/ci.yml`) runs all of these on every push and pull
   request.
3. Commits are SSH-signed; add `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`
   for Claude-assisted work.
4. Deliver automatically: commit, push, and publish the site subtree when
   done, per [spec/repository.md](spec/repository.md#delivery-automatically-commit-push-publish).
   Never force-push or rewrite history without being asked; if the user says
   to hold off, hold off.
