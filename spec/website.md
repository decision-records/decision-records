# Website

`decision-records.github.io/`: SvelteKit 3 with `@sveltejs/adapter-static`,
fully prerendered, styled with the Lily Design System (`@lilydesignsystem/*`
packages, pnpm). Live at https://decision-records.github.io/.

## URL scheme

Every language, English included, is a locale route under its own first path
segment: `/en-us/`, later `/de-001/`, `/cy-gb/`, … There is no separate
English site, and `en` is not a locale slug. One hand-authored English page
sits outside the locale routes: `/skills/` (the Claude Skills promo page).

| URL | Page |
|---|---|
| `/` | Language router (below); nothing else |
| `/skills/` | Claude Skills promo page (hand-authored, English) |
| `/<locale>/` | Landing page of the locale, or search results for `/<locale>/?<query>` |
| `/<locale>/<section>/` | A section index (guide, tutorial, template, examples, checklist, help) |
| `/<locale>/<section>/<dir>/` | One page (an example) |

`<locale>` is any directory name under `locales/` that is in `LOCALES`
(see [locales.md](locales.md)). Search and routing are specified in
[locale-specific-search-picker/](locale-specific-search-picker/index.md).

`/` is the language router: a prerendered static page whose script reads
`navigator.languages` and replaces itself (no extra history entry) with the
visitor's locale route, via `routeForLanguages()` in `src/lib/locales.js`. For
each preference, most preferred first, the first rule that matches wins:

1. the exact locale: `cy_GB` or `cy-GB` goes to `/cy-gb/`, `en-US` to `/en-us/`,
   `en-GB-oxendict` to `/en-gb-oxendict/`;
2. Chinese by script or region: `zh-Hant`, `zh-HK`, `zh-MO` go to `/zh-tw/`,
   `zh-Hans` to `/zh-cn/`;
3. the language's international `*-001` locale: `de-CH` goes to `/de-001/`,
   `en-AU` and bare `en` go to `/en-001/`;
4. any locale of the same language;

A preference that matches nothing is skipped, and with no match at all the
visitor goes to `/en-us/`. Without JavaScript (and for crawlers) `/` stays a
static page with a link to `/en-us/`, which is its canonical URL. Only locales
listed in `LOCALES` are routable, so rules 2 to 4 take effect as locales are
added.

## Locale landing page

`/<locale>/` renders the locale's root `index.md` (the translated README),
loaded by `landingOf()` in `src/lib/server/locale-pages.js`:

- **Hero**: the README's `#` title, a one-sentence subheadline and the
  "Translations: " sentence (listing every `-001` and `en-us` locale), both
  hand-authored in `src/lib/data/hero.js`, and the README's first paragraph.
- **Six cards** linking to anchors further down the same page: README sections
  1, 3, 4, 7, 8 and 9 (see [locales.md](locales.md#root-index-the-translated-readme)).
  A card shows the section's title and its first prose paragraph, clipped to
  about 170 characters.
- **Body**: the README, rendered with `marked` (GitHub alert markers such as
  `> [!IMPORTANT]` are dropped), relative links resolved to site URLs.

With a query (`/<locale>/?<query>`) the hero, cards and body are replaced by
search results.

## Accessibility

The site is checked with axe-core (WCAG 2.2 AA and best-practice rules;
`pnpm run a11y`, run by CI) with zero violations on the home router, landing
pages, section pages, examples, and search results, in left-to-right and
right-to-left locales, at desktop and 390px widths. Rules that keep it so:

- **Contrast in every theme.** The 45 Lily themes differ widely, and their
  accent (`--color-primary`) and "muted" text colours fail AA contrast in about
  half of them. Links and card titles therefore use the theme's text colour
  (`--color-base-content`), underlined. Do not reintroduce `--color-primary` or
  `--lily-text-muted` for text.
- **Phone search.** At 40rem and below, the search field opens over the row of
  picker buttons, full width, inside the header (`src/lib/styles/theme.css`).
- **Keyboard.** Tab order follows the visual order; Enter opens search with the
  field focused, Enter submits, Escape closes it. Code blocks (`<pre>`) have
  `tabindex="0"` because they scroll sideways on narrow screens.

## Generated vs hand-authored

| Path | Kind |
|---|---|
| `src/routes/+page.svelte` | Hand-authored; the `/` language router |
| `src/routes/skills/+page.svelte` | Hand-authored; the Skills promo page |
| `src/lib/components/Header.svelte` | Hand-authored; picker bar and search wiring |
| `src/content/locales/`, `src/lib/locale-pages.json`, `src/lib/locale-peers.json`, `src/lib/locale-sections.json` | Generated by `scripts/sync-locales.mjs` from `locales/` (run by `content`); committed |
| `static/search/<locale>.json` | Generated by `scripts/generate-search-index.mjs` (run by `content`); committed |
| `src/lib/locales.js` | Hand-authored; picker locale list and slug rules |
| `static/sitemap.xml` | Generated by `scripts/generate-sitemap.mjs`; never hand-edit |
| `static/llms.txt`, `static/llms.json` | Generated by `scripts/generate-llms.mjs`; never hand-edit |

Everything the built site needs must live inside the site directory; nothing
may reference `../` at runtime, because the directory is published alone.

## Commands

`pnpm run content` regenerates content and manifest. `pnpm run check` must
report 0 errors before committing changes to `src/`. `pnpm run build` produces
`build/`.

## Dependencies

- The header is Lily's `svelte-picker-bar`, which composes the link, search,
  theme, locale, text-size and share pickers; each package is a direct
  dependency (`svelte-picker-bar`, `svelte-link-picker`, `svelte-search-picker`,
  `svelte-locale-picker`, `svelte-theme-picker`, `svelte-text-size-picker`,
  `svelte-share-picker`), plus `svelte-headless`.
- `typescript` stays on 6.x; SvelteKit 3 requires TypeScript's JS API, which
  7.x lacks.
- `@lilydesignsystem/*` packages track latest; they are exempt from pnpm's
  release-age policy (`minimumReleaseAgeExclude` in `pnpm-workspace.yaml`).

## Themes

`static/themes/<id>.css` are Lily's own generated theme files (45), copied
unmodified from
`https://raw.githubusercontent.com/lilydesignsystem/lilydesignsystem/main/themes/<id>.css`.
Refresh all 45 whenever `@lilydesignsystem/*` packages are upgraded: a package
that adds elements is unstyled by older theme files, which breaks the header
layout. Do not hand-edit them; site-specific styles go in
`src/lib/styles/theme.css`.

## Link picker

The picker bar's leftmost button is Lily's link picker (a home icon). It opens:
**Home** (the locale's landing page), **Guide**, **Template**, **Tutorial**,
**Examples**, **Checklist**, **Help** (the locale's section indexes), **Skills**,
and **GitHub** (the repository, new tab). Hrefs follow the locale being viewed,
because section directory names are translated: `src/lib/locale-sections.json`
(generated by `sync-locales.mjs`; locale to `{kind: directory}`) supplies them.
The current page is marked `aria-current="page"`.

## Language picker

Choosing a locale sets `lang`/`dir` on `<html>`, persists the choice in
`localStorage` (`dr-locale`), and **navigates to the same page in that
locale**, matched through each page's shared `.locale-peer-id`
(`src/lib/locale-peers.json`; `src/lib/locale-nav.js`). If the chosen locale has
no equivalent page, or the current page is not a content page, it goes to the
locale's landing page. Only a user selection navigates; the picker's initial
call must not. The picker shows the language of the page being viewed.
Entries follow [locales.md](locales.md#picker-labels).

## Publishing

```sh
git subtree push --prefix=decision-records.github.io site-origin main
```

(`site-origin` is `git@github.com:decision-records/decision-records.github.io.git`.)
`.github/workflows/deploy.yml` inside the site directory lands at the root of
that repository and deploys to GitHub Pages on each push.
