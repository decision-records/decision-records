## 检查清单：这项决策需要决策记录吗？

只要下列任何一项的答案为**是**，就写一份：

* [ ] 撤销这项决策会代价高昂、进展缓慢或令人难堪吗？
* [ ] 它会影响做决定的那个房间之外的人吗？
* [ ] 一年后是否很可能有人问“我们当初为什么这样做？”
* [ ] 是否存在真正有争议的方案，持不同立场的人都有道理？
* [ ] 它是否确立了其他决策需要与之保持一致的先例或政策？
* [ ] 新员工或该职位的新任领导者了解其中的理由会有帮助吗？

如果下列**所有**条件都成立，则可以不写决策记录：

* [ ] 撤销成本低、速度快。
* [ ] 只影响决策者本人或一个独立的团队。
* [ ] 现有政策、标准或文档已完全涵盖。
* [ ] 明确是临时性的，例如变通办法、试点或限定时间的实验。

## 检查清单：开始写作之前

* [ ] 已确定指定的决策者，可以是一个人，也可以是一个具体的委员会 / 小组决策规则。
* [ ] 已确定真正的利益相关方：在最终定案前需要谁发表意见？
* [ ] 已了解期限或紧迫程度：这必须现在决定，还是可以等待更多信息？
* [ ] 已根据风险高低选择了轻量模板或完整模板（参见 [template/index.md](../模板/index.md#选择使用哪个模板)）。
* [ ] 知道完成后的记录将存放在哪里，避免它丢失在聊天串或某个人的收件箱里。

## 检查清单：写作过程中

* [ ] 标题简短、现在时、主动句，陈述的是决策，而不是话题。
* [ ] 背景向一位毫无会议背景的读者解释了情形。
* [ ] 至少列出两个真正可行的方案，如相关，包括“什么也不做”。
* [ ] 每个方案的权衡都以事实陈述，而不是为了让受青睐的方案获胜而搭建的稻草人。
* [ ] 决策以平实的主动语态书写：“我们将做 X”，而不是用优缺点概括来代替决策。
* [ ] 后果描述接下来发生什么变化，而不是重述方案之争。
* [ ] 如有相关的决策、需求或文档，已加上链接。
* [ ] 全文只围绕一项决策，如果发现有两项，就拆分开。

## 检查清单：发布征求意见之前

* [ ] 一位没有参加讨论的人读完后，既能理解决策，也能理解原因。
* [ ] 没有尚未解决的“你们考虑过 X 吗？”空白，如果很可能被问到的问题没有答案，就补上。
* [ ] 状态设置正确（此阶段通常是 `征求意见` 或 `已提议`）。
* [ ] 明确写明了意见截止时间和流程（例如“周五前提出意见，之后默认接受”）。
* [ ] 记录有一页或接近一页，如果篇幅过长，检查它是否其实不止一项决策。

## 检查清单：评审与批准

* [ ] 每位指定的利益相关方都有真正的机会发表意见，而不只是礼节性抄送。
* [ ] 实质性意见已体现在记录中（作为修改或带日期的补充说明），而不是只被认可然后被忽略。
* [ ] 指定的决策者明确接受、否决或退回，沉默不等于接受。
* [ ] 状态字段已更新以匹配结果（`已接受`、`已否决` 等），并带有日期。
* [ ] 如果被否决或推迟，记录仍保留在日志中而不是被删除，它记录了这个问题曾被提出以及为何没有推进。

## 检查清单：决策之后（推行）

* [ ] 决策已传达给所有受其影响的人，而不只是在场的那些人。
* [ ] “后果”部分所产生的后续需求、预算或培训方面的影响，确实已分配给了某个人。
* [ ] 记录已归入共享的决策日志，而不是留在个人文件夹或聊天串里。
* [ ] 已指定负责人，对这项决策日后的复审负责。
* [ ] 如果这项决策取代了先前的决策，旧记录的状态已更新为 `已被取代`，并带有指向新记录的链接。

## 检查清单：在整个组织中运行决策记录

* [ ] 已确定谁可以 *提出* 决策记录（通常：任何人）。
* [ ] 已确定谁可以 *批准*，以及批准权是否因决策类型、金额门槛或风险级别而不同。
* [ ] 已确定利益相关方出现分歧时的升级路径。
* [ ] 已选定每个相关团队都会真正使用的存放位置。
* [ ] 已选定一种无需项目经理也能采用的命名约定，“决策”往往比“决策记录”更易于接受。
* [ ] 已确定少数几项早期、高可见度的决策先行记录，在强制要求任何事情之前先展示价值。
* [ ] 避免把它变成强制的文书工作，而是把它作为让团队自己的工作更轻松的东西来推行，而不是自上而下的合规要求。

## 检查清单：季度或年度决策日志审计

* [ ] 浏览停留在 `征求意见` 或 `已提议` 而没有结论的记录，把它们关闭或明确归档。
* [ ] 检查已接受且设有复审节奏的决策是否确实得到了复审。
* [ ] 检查那些在实践中被非正式推翻、但从未在日志中标为 `已被取代` 的决策，并更新它们。
* [ ] 抽查几份较早的记录：今天的新员工不问人，能看懂背景吗？
* [ ] 确认日志仍存放在当前团队实际使用的地方，工具和习惯在一年里会发生变化。
