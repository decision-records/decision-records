# チェックリスト

## チェックリスト：この決定に意思決定記録は必要か？

次のいずれかに**はい**と答えるなら、書きましょう。

* [ ] この決定を覆すと、コストがかかる、時間がかかる、あるいは恥ずかしい思いをするか？
* [ ] 決定が行われている場にいない人にも影響するか？
* [ ] 1 年後に誰かが「なぜこうしたのか？」と尋ねそうか？
* [ ] 道理のある人々が別々の側に立つ、本当に意見が割れる選択肢があるか？
* [ ] 他の決定が整合させる必要のある前例や方針を作るか？
* [ ] 新入社員や、この役割の新しいリーダーが、理由を知ると役に立つか？

次の**すべて**が当てはまるなら、意思決定記録は省略してかまいません。

* [ ] 元に戻すのが安く、速い。
* [ ] 影響が意思決定者本人、または自己完結した 1 つのチームにとどまる。
* [ ] 既存の方針、標準、ドキュメントですでに完全にカバーされている。
* [ ] 明示的に一時的なもの — 回避策、パイロット、期限付きの実験である。

## チェックリスト：書き始める前に

* [ ] 指名された意思決定者が特定されている — 1 人、または集団の決め方を定めた特定の委員会／ルール。
* [ ] 実際のステークホルダーが特定されている — 確定の前に誰が意見を述べる必要があるか？
* [ ] 期限や緊急度が理解されている — 今すぐ決める必要があるのか、より多くの情報を待てるのか？
* [ ] 重要度に応じて軽量テンプレートか包括テンプレートかを選んだ（[テンプレート/index.md](../テンプレート/index.md#使用するテンプレートの選び方)を参照）。
* [ ] 完成した記録をどこに保管するかが分かっており、チャットのスレッドや個人の受信箱で失われない。

## チェックリスト：書いている間に

* [ ] タイトルが短く、現在形で、能動的で、トピックではなく決定を述べている。
* [ ] 背景が、会議の知識がまったくない読者に状況を説明している。
* [ ] 実行可能な選択肢が少なくとも 2 つ、必要なら「何もしない」も含めて挙げられている。
* [ ] 各選択肢のトレードオフが、好まれる選択肢を勝たせるための当て馬としてではなく、事実として述べられている。
* [ ] 決定が平易な能動態で書かれている：「私たちは X を行います」— 決定の代わりになる長所と短所の要約ではない。
* [ ] 結果が、選択肢をめぐる議論の蒸し返しではなく、次に何が変わるかを述べている。
* [ ] 関連する決定、要件、文書があれば、リンクされている。
* [ ] 全体がちょうど 1 つの決定に焦点を当てている — 2 つ見つかったら分割する。

## チェックリスト：コメント用に公開する前に

* [ ] 議論に加わっていなかった人が読んで、決定とその理由の両方を理解できる。
* [ ] 未解決の「X は検討しましたか？」という抜けがない — ありそうな質問に答えがなければ追加する。
* [ ] ステータスが正しく設定されている（この段階では通常 `コメント募集中` または `提案中`）。
* [ ] コメントの期限とプロセスが明示されている（例：「コメントは金曜日まで、その後は既定で承認」）。
* [ ] 記録が 1 ページ、またはそれに近い。広がりすぎているなら、実際には複数の決定ではないか確認する。

## チェックリスト：レビューと承認

* [ ] 指名されたすべてのステークホルダーに、形だけの CC ではなく、実際にコメントする機会があった。
* [ ] 実質的なコメントが記録に反映されている（編集、または日付付きの追記として）— 認めただけで無視されていない。
* [ ] 指名された意思決定者が、明示的に承認、却下、または差し戻しを行った — 沈黙は承認ではない。
* [ ] ステータス欄が結果に合わせて（`承認済み`、`却下` など）日付とともに更新されている。
* [ ] 却下または延期された場合も、記録は削除されずログに残る。問いが提起されたこと、そしてなぜ進まなかったかを記録するためです。

## チェックリスト：決定後（ロールアウト）

* [ ] 決定が、その場にいた人だけでなく、影響を受けるすべての人に伝えられている。
* [ ] 「結果」セクションにある後続の要件、予算、研修への影響が、実際に誰かに割り当てられている。
* [ ] 記録が、個人のフォルダーやチャットのスレッドではなく、共有の意思決定ログに保管されている。
* [ ] この決定を将来見直す説明責任を負うオーナーが指名されている。
* [ ] この決定が以前の決定に取って代わる場合、古い記録のステータスが `置き換え済み` に更新され、先へのリンクがある。

## チェックリスト：組織全体で意思決定記録を運用する

* [ ] 誰が意思決定記録を*提案*できるかを決めた（一般的には：誰でも）。
* [ ] 誰が*承認*できるか、そしてそれが決定の種類、金額の閾値、リスクレベルで変わるかを決めた。
* [ ] ステークホルダーの意見が分かれたときのエスカレーション経路を決めた。
* [ ] 関係するすべてのチームが実際に使う保管場所を選んだ。
* [ ] プログラムマネージャーなしで人々が取り入れられる命名規則を選んだ — 「意思決定記録」より「決定」のほうが親しみやすいことが多い。
* [ ] 何かを義務づける前に価値を示すため、最初に記録する、注目度の高い少数の早期の決定を特定した。
* [ ] 強制された事務作業にしないようにした — チーム自身の仕事が楽になるものとして導入し、トップダウンのコンプライアンス要件にはしなかった。

## チェックリスト：四半期ごと、または年ごとの意思決定ログ監査

* [ ] `コメント募集中` や `提案中` のまま解決されていない記録を探す — 完了させるか、明示的にアーカイブする。
* [ ] 見直しの頻度が定められた承認済みの決定が、実際に見直されたかを確認する。
* [ ] 実際には非公式に覆されたのに、ログ上では `置き換え済み` とされていない決定がないか確認する — あれば更新する。
* [ ] 古い記録をいくつか抜き打ちで確認する：今日の新入社員が、誰にも尋ねずに背景を理解できるか？
* [ ] ログがいまのチームが実際に使っている場所に今も保管されていることを確認する — ツールや習慣は 1 年のうちに変わっていく。
