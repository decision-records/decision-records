# รายการตรวจสอบ

## รายการตรวจสอบ: การตัดสินใจนี้ต้องมีบันทึกการตัดสินใจหรือไม่

เขียนหนึ่งฉบับหากคุณตอบ **ใช่** ต่อข้อใดข้อหนึ่งเหล่านี้:

* [ ] การกลับการตัดสินใจนี้จะมีต้นทุนสูง ช้า หรือน่าอับอายหรือไม่
* [ ] ส่งผลต่อผู้คนนอกห้องที่ตัดสินใจกันอยู่หรือไม่
* [ ] มีแนวโน้มที่จะมีคนถามว่า "ทำไมเราทำแบบนี้" ในอีกหนึ่งปีข้างหน้าหรือไม่
* [ ] มีตัวเลือกที่ถกเถียงกันจริงๆ โดยมีผู้มีเหตุผลอยู่คนละฝ่ายหรือไม่
* [ ] สร้างแบบอย่างหรือนโยบายที่การตัดสินใจอื่นต้องสอดคล้องด้วยหรือไม่
* [ ] พนักงานใหม่หรือผู้นำคนใหม่ในบทบาทนี้จะได้ประโยชน์จากการรู้เหตุผลหรือไม่

ข้ามบันทึกการตัดสินใจหาก **ทุกข้อ** เหล่านี้เป็นจริง:

* [ ] ย้อนกลับได้ถูกและเร็ว
* [ ] ส่งผลเฉพาะผู้ตัดสินใจหรือทีมเดียวที่ครบในตัวเอง
* [ ] มีนโยบาย มาตรฐาน หรือเอกสารที่ครอบคลุมครบถ้วนอยู่แล้ว
* [ ] เป็นการชั่วคราวอย่างชัดเจน เช่น วิธีแก้ปัญหาเฉพาะหน้า โครงการนำร่อง หรือการทดลองที่มีกรอบเวลา

## รายการตรวจสอบ: ก่อนเริ่มเขียน

* [ ] ระบุผู้ตัดสินใจที่มีชื่อแล้ว เป็นหนึ่งคน หรือคณะกรรมการหรือกฎเฉพาะสำหรับวิธีที่กลุ่มตัดสินใจ
* [ ] ระบุผู้มีส่วนได้ส่วนเสียจริงแล้ว ใครต้องให้ความเห็นก่อนเรื่องนี้เป็นที่สิ้นสุด
* [ ] เข้าใจกำหนดเวลาหรือความเร่งด่วน ต้องตัดสินใจตอนนี้หรือรอข้อมูลเพิ่มได้
* [ ] เลือกแม่แบบแบบเบาหรือแบบครบถ้วนตามเดิมพัน (ดู [แม่แบบ/index.md](../แม่แบบ/index.md#การเลือกแม่แบบที่จะใช้))
* [ ] รู้ว่าบันทึกที่เสร็จแล้วจะเก็บไว้ที่ใด เพื่อไม่ให้สูญหายไปในกระทู้แชตหรือกล่องจดหมายของคนคนเดียว

## รายการตรวจสอบ: ระหว่างเขียน

* [ ] ชื่อเรื่องสั้น กาลปัจจุบัน และเชิงรุก ระบุการตัดสินใจ ไม่ใช่หัวข้อ
* [ ] บริบทอธิบายสถานการณ์ให้ผู้อ่านที่ไม่มีพื้นฐานการประชุมเลยเข้าใจ
* [ ] ระบุตัวเลือกที่ใช้ได้จริงอย่างน้อยสองตัวเลือก รวมถึง "ไม่ทำอะไร" หากเกี่ยวข้อง
* [ ] ข้อแลกเปลี่ยนของแต่ละตัวเลือกระบุเป็นข้อเท็จจริง ไม่ใช่หุ่นฟางที่สร้างให้ตัวเลือกที่ชอบชนะ
* [ ] เขียนการตัดสินใจด้วยประโยคเชิงรุกที่ตรงไปตรงมา: "เราจะทำ X" ไม่ใช่สรุปข้อดีข้อเสียที่มาแทนการตัดสินใจ
* [ ] ผลที่ตามมาอธิบายสิ่งที่เปลี่ยนไปต่อจากนี้ ไม่ใช่การทวนการโต้แย้งตัวเลือก
* [ ] เชื่อมโยงการตัดสินใจ ข้อกำหนด หรือเอกสารที่เกี่ยวข้อง หากมี
* [ ] ทั้งหมดมุ่งไปที่การตัดสินใจเพียงหนึ่งเรื่อง แยกออกหากพบว่ามีสองเรื่อง

## รายการตรวจสอบ: ก่อนเผยแพร่เพื่อขอความเห็น

* [ ] คนนอกการหารือสามารถอ่านแล้วเข้าใจทั้งการตัดสินใจและเหตุผล
* [ ] ไม่มีช่องว่าง "คุณคิดถึง X หรือยัง" ที่ยังไม่ได้แก้ หากคำถามที่น่าจะเกิดขึ้นยังไม่มีคำตอบ ให้เพิ่มเข้าไป
* [ ] ตั้งสถานะถูกต้อง (โดยปกติคือ `ขอความเห็น` หรือ `เสนอ` ในขั้นนี้)
* [ ] ระบุกำหนดเวลาและกระบวนการแสดงความเห็นอย่างชัดเจน (เช่น "ขอความเห็นภายในวันศุกร์ จากนั้นถือว่ายอมรับโดยปริยาย")
* [ ] บันทึกยาวหนึ่งหน้าหรือใกล้เคียง หากกระจัดกระจาย ให้ตรวจสอบว่าจริงๆ แล้วเป็นมากกว่าหนึ่งการตัดสินใจหรือไม่

## รายการตรวจสอบ: การทบทวนและอนุมัติ

* [ ] ผู้มีส่วนได้ส่วนเสียที่ระบุชื่อทุกคนมีโอกาสแสดงความเห็นจริง ไม่ใช่แค่สำเนาถึงตามมารยาท
* [ ] ความเห็นที่มีสาระสะท้อนอยู่ในบันทึก (เป็นการแก้ไขหรือหมายเหตุที่เพิ่มพร้อมวันที่) ไม่ใช่แค่รับทราบแล้วเมินเฉย
* [ ] ผู้ตัดสินใจที่ระบุชื่อยอมรับ ปฏิเสธ หรือส่งกลับอย่างชัดเจน ความเงียบไม่ใช่การยอมรับ
* [ ] อัปเดตช่องสถานะให้ตรงกับผลลัพธ์ (`ยอมรับ` `ปฏิเสธ` ฯลฯ) พร้อมวันที่
* [ ] หากถูกปฏิเสธหรือเลื่อน บันทึกยังคงอยู่ในบันทึกรวม ไม่ถูกลบ เพราะเป็นหลักฐานว่าเคยยกคำถามขึ้นมาและเหตุใดจึงไม่ดำเนินต่อ

## รายการตรวจสอบ: หลังการตัดสินใจ (การนำไปใช้)

* [ ] สื่อสารการตัดสินใจให้ทุกคนที่ได้รับผลกระทบทราบ ไม่ใช่แค่ผู้ที่อยู่ในห้อง
* [ ] ข้อกำหนดต่อเนื่อง งบประมาณ หรือผลด้านการฝึกอบรมจากส่วน "ผลที่ตามมา" ได้มอบหมายให้ใครสักคนจริงๆ
* [ ] จัดเก็บบันทึกในบันทึกรวมการตัดสินใจที่ใช้ร่วมกัน ไม่ปล่อยไว้ในโฟลเดอร์ส่วนตัวหรือกระทู้แชต
* [ ] ระบุเจ้าของผู้รับผิดชอบสำหรับการทบทวนการตัดสินใจนี้ในอนาคต
* [ ] หากการตัดสินใจนี้แทนที่ฉบับก่อน อัปเดตสถานะของบันทึกเก่าเป็น `ถูกแทนที่` พร้อมลิงก์ไปข้างหน้า

## รายการตรวจสอบ: การดำเนินบันทึกการตัดสินใจทั่วทั้งองค์กร

* [ ] ตัดสินแล้วว่าใครสามารถ *เสนอ* บันทึกการตัดสินใจ (โดยทั่วไป: ใครก็ได้)
* [ ] ตัดสินแล้วว่าใครสามารถ *อนุมัติ* และแตกต่างกันตามประเภทการตัดสินใจ เกณฑ์วงเงิน หรือระดับความเสี่ยงหรือไม่
* [ ] ตัดสินเส้นทางการยกระดับเมื่อผู้มีส่วนได้ส่วนเสียไม่เห็นด้วยแล้ว
* [ ] เลือกที่เก็บที่ทุกทีมที่เกี่ยวข้องจะใช้จริง
* [ ] เลือกข้อตกลงการตั้งชื่อที่ผู้คนนำไปใช้ได้โดยไม่ต้องมีผู้จัดการโปรแกรม "การตัดสินใจ" มักเข้าถึงง่ายกว่า "บันทึกการตัดสินใจ"
* [ ] ระบุการตัดสินใจช่วงต้นที่มองเห็นได้ชัดจำนวนน้อยเพื่อบันทึกก่อน เพื่อแสดงคุณค่าก่อนบังคับใช้สิ่งใด
* [ ] หลีกเลี่ยงการทำให้เป็นเอกสารที่ถูกบังคับ แนะนำเป็นสิ่งที่ทำให้ชีวิตของทีมเองง่ายขึ้น ไม่ใช่ข้อกำหนดการปฏิบัติตามที่สั่งจากเบื้องบน

## รายการตรวจสอบ: การตรวจสอบบันทึกรวมการตัดสินใจรายไตรมาสหรือรายปี

* [ ] ไล่ดูบันทึกที่ค้างอยู่ใน `ขอความเห็น` หรือ `เสนอ` โดยไม่มีข้อสรุป ปิดหรือเก็บถาวรอย่างชัดเจน
* [ ] ตรวจสอบว่าการตัดสินใจที่ยอมรับแล้วและระบุจังหวะการทบทวนไว้ได้รับการทบทวนจริง
* [ ] ตรวจหาการตัดสินใจที่ถูกกลับโดยไม่เป็นทางการในทางปฏิบัติแต่ไม่เคยทำเครื่องหมาย `ถูกแทนที่` ในบันทึก ให้อัปเดต
* [ ] สุ่มตรวจบันทึกเก่าสองสามฉบับ พนักงานใหม่ในวันนี้จะเข้าใจบริบทโดยไม่ต้องถามใครหรือไม่
* [ ] ยืนยันว่าบันทึกรวมยังเก็บอยู่ที่ที่ทีมปัจจุบันใช้จริง เครื่องมือและนิสัยเปลี่ยนไปตลอดหนึ่งปี
