# 単一ベンダーへの集中リスクを減らす

* ステータス: コメント募集中
* 日付: 2026-05-20
* 意思決定者: COO（要確認）
* オーナー: 調達責任者

概要：作業中です。これは、重要なサービスを1つのベンダーに大きく依存している状況にどう対応するかを検討しているチームの出発点です。チームがリスクをどのように設定し、選択肢を議論し、情報を集めるかを示します。決定は記録されていません。

## 課題

社内のリスクレビューで、重要なインフラ支出の大きな割合が単一のベンダーに向かっていることが分かりました。そのベンダーは計画外の障害を起こして顧客向けサービスに支障を出し、契約上の上限がないまま価格を引き上げてきました。現状のまま続ければ、組織は可用性のリスクと、抑制されないコスト増に晒されたままです。

答えるべき問い：

* 私たちが依存しているもののうち、実際にどれだけが集中しているか。ベンダーが失敗したり再び値上げしたりしたら、事業に何が起こるか？
* それらの事象はどれほど起こりやすく、どれほど深刻か。私たちは何を受け入れる用意があるか？
* リスクを減らす現実的な方法は何で、どれだけのコストと速さで実現できるか？
* 安全な撤退またはフォールバックはどのようなものか？

## 前提

それぞれの前提は検証すべきものです。

* **障害と値上げは、一度きりではなく、継続するパターンを反映している。**検証：インシデントの履歴、ベンダーからの連絡、市場価格を見直す。
* **第二のベンダーが、重要なワークロードの一部を許容できる品質で動かせる。**検証：候補を絞り込み、限定的な試行を行う。
* **主要ベンダーは、信頼できる代替案があると分かれば条件を改善する。**検証：他の選択肢を評価しながら、更新提案を求める。
* **段階的な移行により、サービスの中断を避けられる。**検証：技術的な依存関係と、ワークロードの移動に関する契約上の制限を見直す。

## 制約

* どの移行の間も、顧客向けサービスを中断してはならない。
* 契約条件により、ワークロードを移せる速さが制限され、解約時の費用がかかる場合がある。
* 新しいベンダーは、最初のベンダーと同じ基準で評価しなければならない。
* 不明、要確認：データの可搬性、使用中の独自サービス、退出手数料、サードパーティリスクに関する規制上の期待。

## 検討した選択肢

各選択肢について、価値、コスト、タイムライン、必要な能力を見積もり、どのような証拠がチームの考えを変えるかを記録します。

* **リスクを受け入れて監視する。**
  * 価値：当面のコストも労力もない。
  * リスク：障害と価格の両方のリスクが残る。現在の集中度では、リスクレビューが認めないかもしれない。
* **既存のベンダーと、サービスレベル、価格の上限、より良い退出条件について再交渉する。**単一ベンダーのままとする。
  * 価値：価格と説明責任に対処する。
  * リスク：単一障害点は取り除かれない。
* **分散する：重要なワークロードの一部を第二のベンダーへ移し、残りについて主要契約を再交渉する。**
  * 価値：集中を減らす。交渉上の立場を強める。
  * コスト要因：ベンダー選定。移行の労力。一定期間の二重の運用コスト。運用の複雑さの増加（2 通りの手順とスキル）。
  * タイムラインの形：チェックポイントを伴う段階的なもの。
* **第二のベンダーなしにレジリエンスを築く：**バックアップ、テスト済みの復旧手順、のちに切り替えを可能にする設計変更。
* **完全に別のベンダーへ移行する。**混乱が最も大きい。現在のベンダーが受け入れがたい場合にのみ正当化される。

## 論拠

チームが想定すべき論点：

* **リスク選好。**どの程度の依存なら許容できるか？ 誰が決めるか？
* **レジリエンスのコスト。**冗長性には継続的な価格がある。保険は価値があるか、どのサービスに対してか？
* **複雑さ。**2 つのベンダーは運用の複雑さを増す。チームにそのスキルはあるか？
* **ロックイン。**組織は1つのベンダーの独自機能にどれだけ依存しており、移行にはいくらかかるか？

チームがコストとトレードオフを評価する方法：

1. 重要なサービスとその依存関係を特定する。それぞれについて、さまざまな長さの障害が事業に与える影響を範囲で見積もる。
2. 履歴とベンダーの証拠を使って、障害と価格変更の可能性を、不確実性とともに見積もる。
3. 各選択肢のコストを見積もる：移行、二重の運用コスト、ツール、トレーニング、調達、継続的な複雑さ。両ベンダーの退出コストを含める。
4. リスクの期待される低減をコストと比較し、可能性の見積もりへの感度をテストする。
5. 先行指標とトリガーポイントを定義する。たとえばサービスレベルの違反、価格変更、セキュリティ事象。

## 影響

チームが分散を決めるなら、次のことが必要になります。

* 最初のベンダーと同じ基準で、ベンダー選定プロセスを実施する。
* 中断を避ける段階的な移行を計画する。
* 並行して、主要契約を再交渉する。
* 運用の複雑さの増加を受け入れ、ベンダーごとに運用手順書を用意する。
* 目標に達するまで、集中度とサービスレベルの条件を定期的に報告する。
