## 常见问题

**这与会议纪要有什么不同？**
纪要记录的是 *讨论了什么*；决策记录捕获的是 *决定了什么以及为什么*，写得能脱离会议背景独立成立。纪要是决策记录的良好输入，但很少能替代它。

**这实际上需要花多长时间？**
对于你已经理解的决策，一份轻量记录需要 15 至 30 分钟。这段时间很少是浪费的，因为否则你会在今后每一次关于该话题的对话中重复解释同样的理由。把附带成本分析、SWOT / PEST 和多条记录在案的意见的完整记录，留给真正高风险的决定。

**谁应当负责我们的决策日志？**
对其所涵盖的团队或职能负责的人，往往就是一年后原本要凭记忆回答“我们当初为什么这样做？”的那个人。在较大的组织中，可以由一位轻量的治理负责人（例如幕僚长、战略负责人，或各职能轮值的负责人）维护索引，而不必批准每一项具体决策。

**如果决策者与利益相关方意见不一致怎么办？**
先确定 *流程*，再确定 *决策*：预先指明谁拥有最终决定权（一个人或一项明确的规则，例如“达成共识，一周内仍未解决则上报 CEO”）。把不同意见记录在完整模板的“意见”部分，而不是抹去分歧，一份记录完整的异议，在日后重新审视决策时很有价值。

**如果我们后来发现决策错了怎么办？**
这正是记录的用途所在。写一份新的决策记录来取代旧的，说明发生了什么变化（新信息、情况变化或推理错误），并链接回去。出错不是删除轨迹的理由，而是轨迹存在的原因。

**我们需要专门的软件吗？**
不需要。共享盘里的一个 Markdown 或 Word 文件夹、维基空间或版本控制仓库都可以。选你的团队每天都会打开的就行，推行失败，因不熟悉的工具而起的，远多于因缺少功能而起的。

**AI 助手能帮助起草或评审吗？**
可以，而且很有成效，主要有两种方式：（1）根据会议记录或逐字稿起草“背景”和“考虑过的方案”的初稿，由人类决策者修改定稿；（2）对照[检查清单](../检查清单/index.md)评审草稿，找出遗漏的方案、含糊的决策，或只是重述争论的后果。AI 助手绝不应作为指定的决策者，问责始终由个人或委员会承担。

**这不就是官僚作风吗？**
当它被当作对已做出并宣布的决策的事后文书工作强加下来时，它恰恰就变成了官僚作风。当它由真正做决定的人在决定之前用作 *思考工具* 时，它依然有价值。参见指南中的[常见误区](../指南/index.md#常见误区)。

**决策记录多到什么程度算太多？**
如果人们不再阅读日志，就是日志疲劳，说明你在记录那些容易撤销或只影响一个人的决策。把记录限于真正难以撤销、横跨多个领域或很可能被重新审视的选择。参见[检查清单](../检查清单/index.md#检查清单这项决策需要决策记录吗)。

**我们团队不喜欢“架构”或“记录”这个词，名称重要吗？**
对运作机制不重要。有些团队只是把文件夹叫作 `decisions/` 而不是 `decision-records/`，推行就快得多，同一个模板用哪个名字都行。用哪个名字能让你的团队真的写下来，就用哪个。

**一份决策记录可以适用于多个业务单元吗？**
可以，只要这项决策确实是共享的（例如全公司统一的供应商）。但要保持 *一份记录对应一项决策*：如果两个业务单元实际上是出于不同原因做出两个不同的选择，就写两份记录，并把它们链接为相关记录。

## 故障排查

| 症状 | 可能原因 | 解决办法 |
|---|---|---|
| 记录永远停留在“征求意见” | 没有截止时间或没有指定决策者 | 明确补上两者；如果到规定日期仍无异议，则默认接受 |
| 没人读日志 | 低风险记录太多；日志疲劳 | 更严格地应用“是否需要写记录？”检查清单 |
| 记录读起来像优缺点列表，没有真正的决策 | 在决策真正做出之前就写了“决策”部分 | 在决策者真正决定之前，不要把“决策”作为最终内容发布 |
| 团队把它当作文书工作，不愿意写 | 作为强制要求自上而下推行，或只在事后用来为先前的选择辩护 | 重新把它作为团队自愿选择的、日后能节省时间的工具推行，从一个明显有用的示例开始 |
| 没人能找到旧记录 | 没有共享、持久的存放位置或索引 | 建立单一的 `decisions/` 位置，并配一个列出标题、状态和日期的索引页 |
| 决策被悄悄推翻而无人察觉 | 没有取代约定 | 决策改变时，务必写一份状态为 `已被取代` 并链接回去的新记录 |

## 术语表

* **决策记录（DR）**：记录一项重要选择、其背景、考虑过的方案、决策及其后果的文档。
* **决策日志（DL）**：一个团队、职能或组织的全部决策记录的汇编。
* **架构决策记录（ADR）**：这一模式在软件领域的先驱，专注于技术和设计选择。
* **状态**：决策的生命周期阶段：征求意见、已提议、已接受、已否决、已弃用或已被取代。
* **已被取代**：已被更新的决策所替代的决策；旧记录留在日志中并带有指向新记录的链接，而不是被删除。
* **重要需求**：对系统或组织有可衡量影响的需求，这类需求足以使写一份决策记录成为正当之举。
* **知识管理（KM）**：决策记录所属的更广泛的学科：捕获组织知识，使其比任何一个人的记忆都活得更久。
