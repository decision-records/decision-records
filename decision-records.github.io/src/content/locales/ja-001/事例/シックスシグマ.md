# シックスシグマ

* ステータス: コメント募集中
* 日付: 2026-01-19
* 意思決定者: 最高執行責任者（COO）（要確認）
* オーナー: 品質責任者

概要：作業中です。これは、ばらつきと欠陥を減らすためのデータ駆動型の手法であるシックスシグマを、業務に導入する方法を検討しているチームの出発点です。チームが問いをどのように設定し、選択肢を議論し、情報を集めるかを示します。決定は記録されていません。

## 課題

ある業務チームは大量の案件を扱っており、たとえばデータ入力やルーティングのミスのために、かなりの割合のやり直しが必要になっています。やり直しは費用と時間を奪い、顧客からの苦情の主な原因となっています。リーダーは、欠陥を減らすための構造化された方法としてシックスシグマに関心を持っていますが、一度に多くの人をトレーニングすれば現場から人手が奪われること、そして組織のデータが、すべてのプロセスで欠陥を一貫して測定できるほどまだ良くないかもしれないことも承知しています。

答えるべき問い：

* やり直しの問題の実際の規模とコストはどれほどで、現在どれだけ確実に測定できるか？
* シックスシグマはこの問題に適したツールか、それともより単純な修正で足りるか？
* どこから始め、何人の訓練された実践者で、最初のプロジェクトは何か？
* それが機能しているか、拡大すべきかをどう判断するか？

## 前提

それぞれの前提は検証すべきものです。

* **少数の原因が、やり直しの大半を引き起こしている。**検証：やり直し案件をサンプリングして原因を分類し、少数のカテゴリーが支配的かどうかを見る。
* **欠陥を一貫して測定できる。**検証：2 人に同じサンプルの欠陥を数えてもらい、一致するかを見る。必要なデータが存在するかを確認する。
* **訓練を受けた担当者は、通常業務と並行してプロジェクトを実施できる。**検証：DMAIC プロジェクトに必要な時間を、担当者が割ける時間と照らして見積もる。
* **改善は、プロジェクトが終わった後も維持される。**検証：何の管理（モニタリング、オーナーシップ、標準作業）が成果を維持するかを尋ねる。
* **最初に選ぶプロセスは、次のプロセスのための教訓を教えられるほど代表的である。**検証：最初の候補を他のものと、量、ばらつき、データの質で比較する。

## 制約

* 全員を一度にトレーニングすれば、多くの人が現場から離れることになる。
* データの質が、最初の段階で測定できるものを制限するかもしれない。
* 作業の進行中も、顧客対応の品質へのコミットメントは続く。
* 不明、要確認：プロジェクトの節約額を経理部がどう検証するか、組織がどのトレーニングと認定のルートを好むか。

## 検討した選択肢

各選択肢について、価値、コスト、タイムライン、必要な能力を見積もり、どのような証拠がチームの考えを変えるかを記録します。

* **全社に展開し、あらゆる場所のマネージャーにベルトのトレーニングを行う。**
  * 価値：共通の手法がすばやく得られる。
  * コスト要因：多くのマネージャーのトレーニング時間。測定できるようになる前に始まるプロジェクト。マネジメントの注意。
  * タイムラインの形：広範な初期の労力、不均一な結果。
  * リスク：多くのマネージャーが現場から離れる。信頼できるベースラインのないプロジェクト。
* **少数の訓練された実践者と、まず単一のプロセスで採用する。**小さなグループ（たとえばグリーンベルトとブラックベルト）をトレーニングし、量の多いプロセスを 1 つ選び、欠陥率を測定し、DMAIC（定義、測定、分析、改善、管理）を使ってプロジェクトを実施し、その結果を使って次を選ぶ。
  * 価値：データで価値を実証する。必要な場所に能力を築く。
  * コスト要因：トレーニング。プロジェクトの時間。測定システム。スポンサーの時間。
  * タイムラインの形：定義から持続的な管理に至る最初のプロジェクトを行い、目標が定めた期間維持された場合にのみ拡大する。
  * 必要な能力：統計のスキル。スポンサーの支援。信頼できるデータ。
  * リスク：遅い。当初は便益が狭い。
* **外部のコンサルタントを使ってプロジェクトを実施する。**
  * 価値：スピードと経験。
  * コスト要因：報酬。彼らとともに去る知識。
  * リスク：社内にほとんど能力が残らない。
* **まずより単純な問題解決を使い**（たとえばプロセスマッピング、根本原因分析、ポカヨケ）、必要な場合にのみシックスシグマを加える。安上がりで、率直にコストを見積もる良いベースライン。
* **問題がばらつきだけでなく、流れや待ちにも関わる場合は、リーン手法と組み合わせる**（合わせてリーンシックスシグマとして知られる）。

## 論拠

チームが想定すべき論点：

* **問題はばらつきか、それとも別の何かか。**シックスシグマは、プロセスが結果にばらつきを生み、欠陥を数えられる場合に最も強い。ここはそうか？
* **まず測定。**欠陥を数える信頼できる方法がなければ、手法は機能しない。測定への投資が本当の最初のプロジェクトか？
* **深さか広さか。**少数の深いプロジェクトか、広いが浅いプログラムか？
* **節約額の主張。**数字が信じられるよう、節約額はどう、誰によって検証されるか？

チームがコストとトレードオフを評価する方法：

1. 品質不良のコストを組織自身の言葉で見積もる：やり直しの時間、遅延、対応した苦情、失った顧客。範囲で示す。
2. プログラムのコストを見積もる：トレーニング、実践者の時間、測定のセットアップ、スポンサーの時間、ツール。範囲で示す。
3. 期待される便益、便益の確実性、最初の結果までの時間、元に戻しやすさで選択肢を比較する。
4. 価値、コスト、スピード、リスク、残される能力について、重み付け意思決定マトリクスを使う。
5. 最初のプロジェクトでプリモーテムを行い、失敗の各理由を防ぐための管理を加える。

## 影響

チームが単一プロセスから始めることを選ぶなら、次のことが必要になります。

* スポンサーを指名し、実践者を選び、その時間を守る。
* プロジェクトの開始前にベースラインと目標で合意し、前後で同じ方法で測定する。
* データが信頼できない場合は、まず測定に投資する。
* 他のプロセスに拡大する前に、「維持された」とは何か（たとえば目標が定めた期数連続して達成される）を定義する。
* 最初のプロジェクト以外のマネージャーが、自分のプロセスがいつ検討されるかを知っているようにする。
